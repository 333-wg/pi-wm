# 验证效率与浏览器批量操作

## 验证范围

修改前确定本次受影响的行为和最小充分验收检查。优先使用项目已有的定向测试，遵守项目强制检查；共享基础设施、依赖或跨模块修改需要扩大覆盖。相关检查通过且没有未解决疑点后结束，不重复已有的有效验证。

视觉变化仍需检查实际渲染，但静态文案和样式修改不要求遍历无关表单、菜单和页面。普通网页默认桌面视口；移动端范围取决于用户请求和产品定位。批量操作已返回截图、快照或诊断时，不再单独调用同等检查。

常规验证遭遇与修改无关的环境问题时，先检查具体错误，最多进行一次有依据的修复尝试；仍被阻塞则说明未验证部分。数据库或环境本身属于用户要求修改的范围时，不受这条常规验证限制。不能用缩短测试时间为理由忽略已知失败。

纯后端改动默认执行相关自动化检查，只有影响页面行为时才增加浏览器验证。常规浏览器验证以约 60 秒为目标；约 90 秒后停止增加检查并汇报已完成证据和阻塞，用户明确要求广泛测试或发现回归时可说明理由后扩展。这是 Agent 的规划规则，不是跨工具、跨浏览器的硬性计时器；工具内部另有可执行的动作与取证预算。

## 浏览器批量执行

### 浏览器技能优先

用户明确指定浏览器时遵循用户选择；否则优先使用已启用、适用且指令已加载或明确选中的浏览器技能，例如实际接入后的 ego-browser。仅安装技能不代表命令、浏览器连接和运行权限已经就绪，仍须遵循技能激活和权限规则。

一次验证流程使用一个主要浏览器途径。技能提供的实际交互结果、已查看的截图和运行诊断，可以满足对应的检查，不再为了内置工具名称重跑同样的测试。静态页面、移动端覆盖和结束条件仍按本次修改范围确定。

没有可用的适用技能，或技能缺少必要能力时，才回退内置浏览器；说明具体限制，只补缺失检查。权限拒绝、业务断言失败或操作较慢不构成绕过限制、换浏览器重做的理由。两个浏览器的登录、页面、元素引用和日志不能假定共享；补充检查前需确认目标页面和状态。无法获得必要证据时明确报告未验证。

这是一项 Agent 指令策略，不是自动安装 ego-browser 或强制切换后端的程序路由。它也不把任意成功的命令直接算作测试通过。

支持批量的浏览器后端通过现有 `browser_action` 提供 `action: "batch"`：

```json
{
	"action": "batch",
	"steps": [
		{ "action": "fill", "role": "textbox", "name": "Name", "value": "Ada" },
		{ "action": "click", "role": "button", "name": "Save" },
		{ "action": "wait", "text": "Saved: Ada", "state": "visible" }
	],
	"screenshot": true,
	"step_timeout_ms": 5000,
	"timeout_ms": 30000,
	"evidence_timeout_ms": 10000
}
```

- 每批 1–12 步，按顺序执行。支持点击、悬停、填写、逐字输入、勾选、取消勾选、按键、选择和等待元素状态。
- 必须使用明确的 CSS、ARIA 角色或精确文本定位。拒绝旧快照 ref 和歧义定位；执行前检查整批参数。
- `wait` 必须指定预期元素或结果，不支持批量内固定睡眠。应以实际结果断言结束，不能把点击成功等同于业务成功。
- 默认单步最多等待 5 秒，动作阶段总预算 30 秒；最终快照、诊断、截图和产物保存共享 10 秒预算，可用 `evidence_timeout_ms` 调整为 100–30000 毫秒。中间不生成页面快照，最后统一返回证据。`durationMs` 包含最终截图和保存等待，`actionDurationMs`、`evidenceDurationMs` 分别记录动作与取证阶段；等待用户授权的时间不计入。
- 取证超时会停止等待、标记缺失证据，并保留已完成步骤；正在进行的批量页面快照或截图会关闭其操作页面以取消浏览器等待。产物写入会收到取消信号；不支持取消的存储后端可能稍后完成写入，但该结果不会被误报为本次已成功保存。其他浏览器会话不受影响。
- 失败后停止后续操作，在错误中保留 `completedSteps`、从 1 开始的 `failedStep`、页面快照和诊断。成功时才附截图；失败后的视觉定位可单独截图。截图失败也会明确报告，不能假装完成视觉验证。
- 取消执行会关闭该批次正在控制的自动化页面，以终止进行中的等待和点击。其余浏览器会话不受影响。
- 部分完成后的失败批次，在本轮不能通过更改截图或超时选项原样重跑；检查现场后只提交必要的剩余步骤。新一轮重新开始恢复记录。
- 所有动作沿用现有权限检查；只读会话不提供交互工具。下一步依赖未知页面内容时，继续使用单步操作。
- 标签页或网站来源改变后停止后续步骤，先检查新页面并重新走权限检查，不沿用原网站的授权继续操作。

原有单步 `browser_action` 参数保持兼容。

## 页面快照

短小但已经有可见控件的本地页面不再仅因文字不足等待两秒；显式 `wait_for` 仍按指定条件等待。研究网页的内容证据规则保留，避免把未加载内容当成已读事实。设置 `selector` 时，交互引用与语义树都限制在该区域内。

## 预览服务

先查询 `preview_status`。它返回本会话状态，以及同一工作区其他会话管理的 `workspacePreviews`；本会话显示 `stopped` 不等于整个项目没有运行服务。

同一会话对相同命令、工作目录和 URL 再次调用 `preview_start` 时，会复用仍然健康的进程。其他会话已占用的地址、正在启动的相同地址或已经响应的外部服务会被明确报告，不会被自动接管或停止。

只有明确的连接拒绝才视为尚未监听。响应超时、TLS 或其他探测错误标记为“状态未知”，不会因此启动第二个命令，也不会停止已有进程。查询结果提供其他会话的启动命令和工作目录，供确认应用身份。

内置浏览器操作自动持有匹配工作区预览的使用租约，多个借用者全部释放后才重新开始空闲计时。服务启动阶段不计入空闲回收。使用外部浏览器技能时，可调用 `preview_status` 并传入 `url` 为选中的服务续期；仅查看服务列表不会续期其他服务。用户明确停止服务和应用关闭仍会终止进程。

启动就绪要求 HTTP 2xx/3xx；HTTP 4xx/5xx 不算就绪。可以使用专门的健康检查 URL。该判断不是业务验收，也不能完全识别不受管理进程在端口探测后抢占地址的竞态。

本次没有修改具体业务项目的数据库或操作系统配置；这些故障仍需按实际原因处理。
