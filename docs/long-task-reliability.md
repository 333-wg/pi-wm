# 长任务执行与故障恢复

## 超时边界

- 整轮任务默认没有固定时长上限：`WUMING_TURN_TIMEOUT_MS=0`。显式配置正数仍可设置整轮期限。
- 模型流默认连续 10 分钟没有事件时退出当前请求，记录 `provider_timeout` 并进入有次数上限的恢复流程。流中有事件会刷新计时，不按整轮时长中断持续输出。
- 独立网关可用 `WUMING_MODEL_IDLE_TIMEOUT_MS` 配置模型流静默阈值。长时间不返回任何事件的推理渠道可以调大；`0` 关闭此保护。桌面宿主会隔离外部 `WUMING_*` 环境变量，使用构建默认值，不能通过修改系统环境变量调整此项。该阈值不是上游可用性保证。
- 模型请求结束即清理流计时器，执行工具、等待子任务不占用模型静默时间。工具仍保留各自的执行期限。
- 手动停止优先于恢复，不因停止而自动重试。Windows 命令停止会清理进程树；已取消的命令不会被启动。

## 环境与恢复

- 工作区命令继承用户工具路径、代理及普通环境，但不继承宿主的 `WUMING_*`、`ELECTRON_*` 或 Node IPC 变量。这样命令启动的测试服务不会误入桌面宿主模式，也不会意外使用宿主数据库或连接令牌。
- 桌面模式还移除宿主注入的 `NODE_ENV=production` 与 `PLAYWRIGHT_BROWSERS_PATH`，避免项目安装时省略开发依赖或误用桌面内置浏览器；独立网关下保留用户显式提供的这两项配置。
- 模型失败后的续执行保留已完成的工具结果。未知结果的操作必须先检查状态，不自动重放外部副作用；这不是对任意工具的严格 exactly-once 保证。
- 错误诊断保留可获得的 HTTP 状态、嵌套连接错误码和请求标识，限制长度并过滤常见凭据；不导出完整请求头或响应体。
- 运行诊断区显示当前命令、执行时长、最近输出时间，区分执行工具与等待模型。旧记录未记录输出时间时不伪造时间。

## 验证

```sh
npx vitest run packages/pi-adapter/test/model-stream.test.ts packages/pi-adapter/test/model-idle-recovery.test.ts packages/pi-adapter/test/provider-error.test.ts packages/sandbox/test/local-process.test.ts packages/orchestrator/test/turn-timeout.test.ts apps/web/test/run-diagnostics.test.ts
npx playwright test e2e/long-task-diagnostics.spec.ts
```

本地 HTTP/SSE 集成测试覆盖：工具静默执行超过模型阈值、下一请求无响应、关闭失效连接、自动恢复并保留工具结果，确认测试中的写操作仅执行一次。虚拟时钟测试覆盖一小时整轮运行、持续模型输出、手动停止和显式期限。模拟服务与自动化测试不能保证第三方服务永远在线。

这些是工作区修复，只有包含相应源码的新桌面构建才会生效；既有 0.1.9/0.1.10 安装包不会因修改工作区而改变。
