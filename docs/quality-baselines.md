# 质量基线与核心回归

这组检查聚焦已有工作流的可靠性，不触发收费模型，也不替代安装包或真实模型验收。

## 核心浏览器门禁

```sh
npm run test:e2e:install
npm run test:e2e:core
```

`playwright.core.config.ts` 明确列出六个测试文件，覆盖审批失败后的重试、历史编辑、后续消息队列、真实 Pi 适配器的刷新和网关重启恢复、长会话渲染，以及团队卡片的长文本布局和 8 套主题状态色。当前共 23 个用例；Pi 适配器测试仅连接本机模拟 HTTP/SSE 服务。

- 每个测试服务使用临时目录、随机端口和专用数据库，不连接正在使用的桌面实例。
- 单 worker、零自动重试、总超时 10 分钟；失败不通过自动重跑掩盖。
- 主 CI 在类型检查与单元测试之后执行核心门禁。完整 E2E 套件仍按变更风险单独运行。
- 本地报告在 `playwright-report/core/`，失败截图、录像、trace 和性能 JSON 在 `test-results/core/`。CI 无论成功或失败都尝试保留这些证据 14 天。

## 长会话性能

```sh
npm run test:performance
```

测试使用 100、500、2000 条固定结构消息，在 1440px 与 390px 下测量。每轮包含用户消息、过程消息、工具结果和最终回答。每个用例拥有独立数据库，每个视口记录三次导航：首次加载和两次刷新。

`metrics.json` 包含导航至目标历史可见的耗时、聊天 DOM 节点数、已挂载过程节点数，以及 Chromium 当时报告的 JS 堆大小。

注意：

- 这是 Vite 开发模式、合成历史数据的基线，不是正式安装包启动速度或真实用户 P95。
- 耗时包含加载和 Playwright 断言等待；首次加载与热刷新须分开比较。
- 堆大小受垃圾回收时机影响，不能直接宣称精确内存节省比例。
- 自动门禁断言的是未展开过程不挂载内部节点、内容可见、无页面异常和无水平溢出。耗时只记录，不使用机器相关的硬阈值。
- 整轮过程改为首次展开才挂载；展开后再次折叠仍保留组件，避免丢失工具详情状态。这不是全历史虚拟化，已浏览很多过程时内存仍可能增长。
- 原始记录和服务端搜索不受影响；搜索命中会先展开再定位。回归还检查刷新、在长历史末尾编辑真实任务、流式输出期间保持阅读位置，以及停止任务。
