# 缓存优化实施说明

实施日期：2026-09-15。基于当前项目和实际安装的 Pi 0.84.3，继续落实 [第一轮调研](prompt-cache-review-2026-09-15.md)。

## 默认生效的优化

1. **上下文入选和渲染排序分离。** 相关性继续决定预算不足时选择哪些片段；入选后，stable、session、turn 均按作用域、必需性、固定优先级、类型权重和 ID 排序。相同内容不会仅因提问措辞不同而重新排列。文件更新、Skill 选择变化、预算裁剪仍如实改变内容。
2. **工具清单与 schema 稳定化。** 工厂统一按名称注册工具，递归规范化 schema 对象键顺序，不修改调用方对象。仅对 schema 的 `required` 字段名集合排序，保留其他数组顺序、工具执行函数、参数准备函数与校验语义；重复工具名称显式报错。真实工具定义或权限变化仍然生效，不会为了保缓存继续暴露已撤销工具。
3. **日期后移。** 每次构建基础系统提示时，当前日期位于固定指令之后，避免跨日重新创建会话时从提示开头打断匹配。日期仍属于 system 提示，没有把权限或政策规则降级到用户消息。这不意味着跨日仍能命中全部历史；日期之后的部分依然可能重新计算。
4. **沿用持久会话标识。** 没有生成随轮次变化的新 cache key，也没有改成所有用户共用一个固定 key。继续由 Pi 的持久会话与各 provider 适配器处理。

这些优化在加载新代码的网关中生效。已经启动的网关需要重启；本次没有终止用户的运行中任务。排序或基础提示结构首次切换到新版本时可能发生一次缓存重建。

## 请求统计实时更新（2026-09-16）

此前上下文占用在每次模型响应结束时更新，但缓存面板只读取整轮结束后提交的 `usageByTurn[].requests`。因此长工具循环的首轮会出现上下文已有数值、缓存统计却显示暂无数据的情况，并不代表服务商没有命中缓存。

- Pi 在每次请求结束后通过 `onRequestUsage` 上报用量；网关先持久化 `session.request.usage.updated` 事件与快照，再发送小型增量事件给前端，不推送整份聊天记录。
- `usageRequests` 按会话内 `requestId` 去重；重复观察更新原记录，整轮结束补齐遗漏记录。它独立于原有费用账单，不改变预算、费用或工具账单的结算时机。
- 旧快照从已有逐请求汇总初始化，不从聊天内容或整轮总量推测缓存。分叉会话不继承源会话的缓存账单。
- 刷新、重连、后续失败或停止任务后，已经保存的请求用量仍可展示；尚未返回的用量不作估计。首次等待显示“等待首个请求用量”，明细标签为“最近完成请求”。
- SDK 仍会将缺失的缓存字段归一化为零，本次不声称能区分“未上报”和“明确零命中”。也没有请求缓存保温、修改缓存 key 或调用真实收费接口。

相关验证：`packages/orchestrator/test/request-usage.test.ts`、Pi adapter 请求回调测试、协议与 reducer 测试、前端用量测试，以及 `e2e/context-usage.spec.ts` 中的运行中刷新、停止和结束去重场景。`/demo-cache-live` 仅在 demo runtime 提供模拟数据。

已运行的网关需在任务结束后重启以加载新逻辑；无需修改 SQLite 表结构。本次未重启用户服务。

## 增量参考上下文与请求诊断（2026-09-24）

网关默认启用以下优化，不需要更改服务商或缓存保留设置：

- **参考数据后置。** README 和媒体模型当前配置明确标记为参考数据；固定媒体规则、AGENTS.md、权限和显式 Skill 指令仍在 system。系统提示明确最近参考快照完整替代历史快照，缺失记录不能作为当前证据。未标记的数据和所有政策保持原有投递方式。
- **只追加变化。** 通过 Pi 的 `before_agent_start` 生命周期加入隐藏自定义消息，由 SDK 持久化；不重写历史消息。相同快照仍在有效历史中时不重复发送，重启后同样去重。压缩移除快照后重新发送当前版本；此检查发生在 Pi 自己的前置压缩之后。删除或裁掉全部参考记录时追加空快照，避免旧版本继续被当成当前状态。
- **预算与恢复。** 系统内容、参考数据和包装文本共享现有注入预算；仍使用相关性选择、明确的截断策略和必需片段失败条件。计划新增可选的参考 token 估计与投递位置，旧计划仍可验证。审批恢复没有新用户请求，保守使用原来的 system 注入方式，允许缓存重建，不重放用户请求或工具。
- **真实请求诊断。** 在 SDK 的 `onPayload` 回调中，保留已有回调及替换结果，对序列化后的工具、system、历史和请求参数计算 SHA-256 摘要。逐请求记录首个变化类别、消息公共前缀长度及请求间隔，不保存额外的提示正文、端点、缓存 key 或密钥。忽略 Anthropic 移动的缓存标记，但不忽略工具参数中恰好同名的字段。
- **面板与持久化。** 上下文统计的“用量明细”显示最近完成请求的前缀变化，诊断导出包含摘要及读写 token。正在等待响应的请求不会覆盖上一条完成请求的缓存统计。诊断随原有请求用量事件保存，无需数据库迁移。
- **恢复请求参数。** 首次强制工具调用仅应用于空的新会话；恢复已有历史时不再重复强制调用工具。

诊断不是服务商缓存状态：`first_observation` 表示当前观察器没有前一个请求，不等于冷启动；`append_only` 不保证服务商缓存未过期。观察器在会话对象重建后重新开始，未支持的协议以及独立压缩请求不伪造诊断。公共消息前缀数量不是缓存 token 数量；实际命中率仍只使用接口上报的用量。

本轮保留了团队政策、Skill 目录、显式 Skill 选择变化和权限变化导致的合理前缀变化，没有冻结这些规则，也没有全局强制长 TTL、保温请求或修改真实模型配置。需要在任务结束后重启使用源码的网关或重新构建桌面应用才能加载新逻辑。

验证包括三种真实 SDK 序列化协议的本地 SSE 测试：续聊、关闭恢复、参考更新与删除保持 system 和已有历史稳定，相同参考不重复追加，政策更新立即生效；另外覆盖参考预算、压缩后补发、审批恢复、诊断协议和用量持久化，以及桌面/移动缓存面板。测试里的命中 token 为脚本化数据，不能据此报告真实服务商的命中率提升。

本轮最终回归：Pi adapter、context engine、请求用量持久化、上下文占用、协议、媒体规则和前端诊断共 24 个测试文件、304 项通过；`npx playwright test e2e/context-usage.spec.ts` 的 4 项通过；`npm run build` 通过，保留现有的大 chunk 提示。桌面和 320px 移动端截图已检查。没有运行真实收费模型基准，也没有重启用户正在使用的服务。

## 缓存准确性与证据加固（2026-09-24）

本次在上述实现上继续加固，以下规则取代早期“缺失缓存字段可能显示 0”的展示行为：

- **字段证据与数字分离。** `cacheUsageEvidence` 分别记录读取、写入字段是否被观察到。对支持的 HTTP SSE 协议，透传检查原始响应 usage，不额外发请求、不 tee 或提前消费整个响应，不保存正文、请求头或密钥。缓存数字仍由 Pi 解析；新增记录不是服务商缓存库存或独立计费审计。
- **明确零值才算已知零。** 缺失缓存字段不再被前端直接认作零命中。旧记录和未覆盖传输只能保守使用已有正缓存计数；零值保持未知。WebSocket、不支持的协议、非 SSE 响应以及超出检查大小上限的帧可能没有字段证据，不能据此断言未命中。仍应以服务商账单核对真实性。
- **已知请求的 token 加权比率。** 命中率分母只包含有读取数据的普通推理请求；同时显示“读取数据可用 N/M 次”和已知请求输入 token。它是有覆盖率边界的统计，不代表全部请求的真实总体比率；升级前后比例不能直接做性能比较。全部已记录输入与费用不删减。未完整上报的读写合计显示 `--`，避免把部分数据伪装成完整总数。
- **区分请求用途与演示。** 新增 `purpose: inference/compaction`；已标记压缩不进入普通推理命中率，面板显示排除数量，费用仍保留。旧记录无法可靠反推用途，不进行猜测迁移。演示请求标记 `dataSource: demo`，面板持续标注“演示数据”，不把脚本化数字当成真实服务商性能。
- **团队前缀稳定。** 固定角色、权限与协作政策仍在 system；成员工作状态、模板候选、依赖就绪情况和任务看板拆成后置参考快照，沿用增量追加、撤销空快照、预算与压缩恢复机制。成员或任务状态变化不再直接改写固定团队 system。团队结束等真实政策变化仍立即生效；审批恢复保留保守路径。

字段沿原有逐请求事件和快照持久化，不需要 SQLite 迁移。没有修改 SDK 依赖、显式 Skill 权限层级、压缩算法、模型配置、TTL 或安全校验，没有发送收费保温请求。

验证覆盖：三种真实 SDK 序列化协议的本地 SSE、明确零值与缺失字段、字段别名、碎片响应、大小上限、重试清理、用量持久化与去重、团队政策稳定和状态更新、压缩用量保留，以及桌面/移动缓存面板。模拟响应只验证协议与展示，不证明线上命中率提高。真实验收仍需固定 provider/model、请求间隔和任务，对普通续聊、空闲恢复、政策变化、压缩分别记录缓存读写、数据覆盖率、费用与首 token 延迟。

本轮验证结果：相关 27 个测试文件、464 项测试通过；`npx playwright test e2e/context-usage.spec.ts` 的 4 项通过；`npm run check`、`npm run build`、`git diff --check` 通过。实际预览在 1440×900、390×844 视口完成展开交互与截图检查，另复核了 320px 暗色长数字场景。新预览页面最终浏览器诊断无错误；初次预览端口冲突已通过换端口解决，没有终止占用该端口的原有服务。构建保留既有大 chunk 提示，范围 lint 无错误，协议文件既有未使用导入警告未改动。

部署后需在任务结束时重启网关或重新构建桌面应用加载新逻辑。本次没有重启用户正在使用的真实服务。

## 压缩恢复与跨日正确性修复（2026-09-24）

- **压缩后续跑补齐快照。** 除新请求的 `before_agent_start` 外，在 `session_compact` 成功事件中检查有效历史；缺失时用 SDK 的隐藏自定义消息补发当前快照并持久化，显式使用 `triggerTurn: false`。压缩已经保留的相同快照不重复追加，空快照也会恢复，避免重新激活已删除的参考。不会为了恢复快照单独发起模型请求。
- **只刷新程序拥有的日期。** 默认提示在上下文组装、新请求开始及每次模型调用时按上海日期刷新，因此复用会话、工具循环、自动续跑或审批恢复跨日也不会继续发送旧日期。只替换已识别的默认日期字段，固定指令和追加的政策原样保留；自定义 builder 和项目 `SYSTEM.md` 不被重写。同日没有提示变化，跨日仍允许日期之后的缓存正常重建。
- **规范化必填字段集合。** schema 遍历区分子 schema、属性映射与普通 JSON 数据，排序各级 `required` 字段名集合；不排序 `enum`、组合分支、元组或 `const/default/examples` 中的数组，也不把名为 `required` 的业务属性误当 schema 关键字。
- **恢复成功不再误报整轮失败。** 整轮结论采用最后一个 assistant 响应；早先失败后的成功响应可以结束任务，最终仍失败时保留原有失败处理。所有失败及恢复请求的用量和诊断继续保留，不通过删除失败记录美化统计。

新增 `packages/pi-adapter/test/prompt-cache-lifecycle.test.ts`，用本地 HTTP/SSE 端点驱动实际 Pi SDK，覆盖连续跨日、自定义提示、工具循环跨日、溢出压缩续跑、空快照、已保留快照、重启去重、阈值压缩不额外调用及手动压缩恢复。原三协议 wire 测试改用必填参数，验证同义工具 schema 重排不会改变请求工具前缀。模拟用量不能证明真实服务商命中率提升。

验证结果：Pi adapter、context engine、请求用量持久化、上下文占用与前端统计共 24 个文件、313 项测试通过；`npm run check`、`npm run build`、本次改动的 oxlint、Prettier 检查及 `git diff --check` 通过。构建保留现有的大 chunk 提示。本轮没有运行浏览器 E2E、真实收费端点基准或整个仓库的全部行为测试。

无需数据库迁移或修改模型配置、TTL。运行中的网关需在任务结束后重启，桌面应用需重新构建部署；本次不自动重启用户服务。

## 保留时长配置

新增可选网关变量，见 `.env.example`：

```dotenv
# 不配置时保留 Pi/provider 默认值及现有 PI_CACHE_RETENTION 行为。
WUMING_PI_CACHE_RETENTION=long
```

| 值     | 行为                                                                  |
| ------ | --------------------------------------------------------------------- |
| 未配置 | 不覆盖 SDK 默认策略，也不覆盖已有 PI_CACHE_RETENTION 环境配置         |
| short  | 显式向 Pi 指定短缓存偏好；具体 TTL 由 provider/model 决定             |
| long   | 显式向 Pi 指定长缓存偏好，由适配器按兼容配置映射                      |
| none   | 移除 SDK 的显式缓存控制和相应会话缓存 key；不能保证关闭服务商自动缓存 |

非法值在初始化时明确报错，不静默当成开启缓存。SDK 调用方也可通过 `createDefaultPiSessionFactory({ cacheRetention })` 配置相同策略。

当前安装版本中，支持长保留的 Anthropic 路径映射为 1h，支持长保留的部分 OpenAI 路径映射为 24h；明确声明 `supportsLongCacheRetention: false` 时不发送长 TTL。第三方接口未声明能力时，SDK 可能采用自己的默认能力判断，所以仍需针对真实端点核实。较新 OpenAI 模型的缓存字段有代际差异，不能把该选项当成所有模型通用的 24 小时保证。

没有为用户全局强制 long，没有修改真实密钥或模型配置，也没有发送用于保持缓存活跃的收费请求。它影响普通 agent 请求；Pi 自身的压缩请求仍使用其专门策略。

## 没有冒进的改动

- 没有冻结 AGENTS.md、README、Skill 或权限状态，也没有为了命中率保留过期政策。
- 没有把政策整体搬入普通用户消息。Pi 的自定义消息最终会转成 user 角色；完整的增量上下文设计还需要同时解决权限层级、撤销、历史残留和压缩后的恢复，不能只移动字符串。
- 没有改动预算相关的选择、必需片段失败条件、截断规则和自动压缩机制。
- 没有宣称真实命中率提升百分比。下一步应在用户实际端点上，固定模型、任务和请求间隔，分别测量首次请求、正常续聊、空闲恢复、Skill 变动和压缩后的 token 加权命中率、成本与首 token 延迟。
