# 停止响应、技能权限、项目侧栏与 Git 信任恢复

## 已确认的问题与修改

- 停止按钮仅在请求失败或任务变为空闲时解锁；服务端已确认停止、但结束事件未到达时，会一直禁用。现在请求结束即解锁，并主动刷新会话快照。
- 网关断线时停止请求直接报错。现在已知运行任务可以最多等待 8 秒完成重连，再发送停止请求；超时、切换会话或切换登录状态后不再补发。停止回执另有 8 秒超时。
- 延迟停止携带原任务 ID，服务端只中断匹配的当前任务，避免重连后误停后续任务。未拿到任务 ID 时仅允许在线立即停止。
- 项目树、展开项目和内部会话列表原来同时收缩与滚动。现在由整个项目树统一滚动，项目默认显示 5 条，提供“展开显示 / 收起显示”；当前选中的会话即使较旧也保留在预览中。标题使用渐隐，操作按钮在交互时出现。
- 完全访问此前允许安装技能，但读取和编辑 `SKILL.md` 被强制审批规则拒绝。现在可信文件工具遵从当前完全访问权限；“始终询问”仍要求审批。目录扫描、读取源码与正式调用是不同步骤，禁用和仅手动调用的规则仍有效。
- 技能管理增加“复制到用户全局”入口。保留项目原件、拒绝覆盖全局同名技能，完成后显示结果。未启用的技能需先启用，避免复制时悄悄激活。
- 对话输入框旁的分支菜单原来遇到 Git `dubious ownership` 只显示错误，且把无法读取分支误标成“分离 HEAD”。现在显示“需信任仓库”，展示准确目录并提供“信任此仓库 → 确认信任并重试”，成功后刷新分支，失败后可重试；原始诊断默认折叠。窄窗口下完整展示确认区域。
- 信任操作仍要求本机写权限和用户确认，仅添加准确的项目根目录，不添加通配符或上级目录。写入后检查 Git 是否实际恢复，配置被更高优先级覆盖时明确报错；重复重试不反复添加有效条目，也允许恢复被空配置重置的旧条目。

## 本机调查

只读取目录和元信息，没有修改或迁移用户已经安装的技能。

抽查的项目级 `.wuming/skills/<id>/SKILL.md` 可以被现有目录系统发现并完整加载。普通 `skills/` 目录和项目根目录的 `SKILL.md` 不属于自动发现目录。目录检查不足以确定历史会话中某个技能调用失败的具体原因，仍需对应会话日志。

Pi-Wm 当前目录范围：

| 位置                                                 | 可用范围               |
| ---------------------------------------------------- | ---------------------- |
| `<项目>/.wuming/skills/<id>/SKILL.md`                | 当前项目               |
| `~/.wuming/skills/<id>/SKILL.md`                     | 本机当前用户的所有项目 |
| 普通 `skills/`、`.agents/skills/`、`.claude/skills/` | 目前需导入到上述目录   |

同名优先级为项目、用户全局、内置。开启完全访问不会改变目录范围；当前项目没有的技能不会仅因权限变大而自动出现。项目内普通技能包可以在管理窗口填写相对目录安装，默认目标为用户全局。

## 外部设计调研

2026-11-26 直接阅读以下官方资料：

1. Agent Skills 格式规范：<https://agentskills.io/specification>
2. Agent Skills 客户端实现指南：<https://agentskills.io/client-implementation/adding-skills-support>
3. Claude Code 技能文档：<https://code.claude.com/docs/en/skills>

Agent Skills 指南建议区分项目与用户范围，并支持 `.agents/skills` 互通目录；同时采用目录摘要、按需加载指令、按需读取资源的分层方式。Claude Code 文档也区分个人、项目和额外目录，文件访问权限与额外目录的配置加载不是同一件事。不同产品的同名覆盖策略并不完全一致，不宜假定可以直接互换全部行为。

本次采用的设计是：完全访问统一授权体验，技能范围显式可见，跨项目复用提供一次点击的全局复制。继续保留小目录摘要和按需加载，避免把整个磁盘上的所有技能塞入上下文。

后续可扩展“添加技能目录”：显式添加 `.agents/skills`、`.claude/skills` 或自选目录，显示真实来源、同名覆盖和不可用原因。该功能尚未实现，不自动扫描其他项目，也不声称完整兼容其他工具的钩子、命令或权限语义。

- 人工查看项目侧栏截图，以及 390px 窗口的 Git 信任确认截图。

测试使用隔离的 Git 用户配置，不修改本机 Git 信任列表；未操作截图中的 Windows 项目。网络故障通过模拟断线和重试验证，未在真实中转站故障期间测试，也未在 Windows 实机验证。初次源码验证不运行全量测试和安装矩阵。后续 v0.1.28 的安装包验证与发布记录见 `docs/releases/v0.1.28.md`。
