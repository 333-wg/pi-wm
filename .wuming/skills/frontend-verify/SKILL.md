# 触发条件

任务改变页面实际渲染、浏览器特有行为或需要补足页面交互验证。仅修改前端目录里的纯逻辑、注释或格式，不自动触发浏览器检查。

# 执行规则

- 先确定受影响行为及最小充分检查，遵守项目明确要求。纯逻辑优先相关自动化测试和适用的类型检查；脚本存在不代表每次必须运行。
- 文案、颜色、间距等视觉修改，只查看受影响画面及可用的运行诊断，不增加无关交互或整站巡检。
- 交互修改优先复用已有的有效自动化证据；只有缺少覆盖或存在具体浏览器风险时，补一条对应流程。构建通过不能代替交互或视觉验收。
- 先查询并复用身份匹配的健康预览服务，再按需启动。不要为了验证重新启动现有服务。
- 普通网页默认桌面；仅在任务、受影响功能或目标产品要求时检查移动端，不把范围外的手机检查报告为缺陷。
- 已知步骤默认使用当前浏览器提供的批量能力，把动作、等待明确结果、最终必要截图或诊断放在一次调用中；下一步依赖未知页面状态时再拆开观察。已有结果中的截图或诊断不重复获取。

# 验证门槛

必要检查通过、证据适用于最终修改且没有相关疑点后立即结束。不额外增加全量测试、第二种浏览器或复审循环。视觉任务需要实际查看图片；交互任务需要明确结果断言，点击成功不等于业务成功。已有测试能防止目标回归时，不重复增加同类测试。

相关源码、测试、依赖、配置和环境未变化时复用成功证据；无关文档修改或准备提交不使其失效。影响范围未知、权限、迁移、安装更新或公共依赖变化时，按风险扩大验证。发现相关失败必须处理，不能降低断言或把未选中测试当作通过。

常规浏览器检查以约 60 秒为目标，约 90 秒后停止新增可选检查。必要检查受阻时明确说明，真实回归或用户要求广泛验证时解释延长原因；时间目标不等于通过条件。

# 失败降级

端口冲突先确认已有服务身份，不停止其他会话的服务；只有确需独立服务时才选择空闲端口。状态不确定时检查现场，失败批次只补必要的未完成步骤，不重放已成功的副作用。无关环境故障最多做一次有依据的修复尝试，仍受阻则报告未验证部分。
